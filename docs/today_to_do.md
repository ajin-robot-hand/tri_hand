# 오늘 할 일: 30분 집중 부하·발열 한계 시험 (2026-10-14)

무부하 공회전으로 24시간을 돌리는 대신, **실물 손에 실질적인 파지 부하(또는 그립 순환)를 주어 30분간 집중적으로 발열·통신·복구 지표를 측정**합니다 (전략 C의 시험 2: 집중 한계/복구 시험).
작업자가 옆에서 지켜볼 수 있는 30분 동안 **모터 온도 상한(65 °C) 안전장치, 통신 안정성, 하드웨어 오류 복구**를 안전하고 확실하게 검증합니다.

| 단계 | 내용 | 예상 시간 |
| :--- | :--- | ---: |
| 0 | 시험 방식 이해 (왜 30분 집중 시험인가) | 3분 |
| 1 | 준비 (하드웨어 및 파지 대상물 세팅) | 5분 |
| 2 | 사전 점검: 관절 간섭 및 부하 확인 (완료) | 5분 |
| 3 | 2분 퀵 리허설 (선택) | 5분 |
| 4 | 본 시험 시작 (30분 집중 구동) | 30분 |
| 5 | 시험 중 모니터링 (온도 및 대시보드) | 수시 |
| 6 | 종료 후 판정 및 기록 | 10분 |

> 모든 명령은 리포지토리 루트(`c:\workspace\tri-hand`)에서 실행합니다.
> 파이썬은 가상환경(`mujoco_env`) 활성화 상태에서 `python`을 사용합니다.
> Windows 환경에서는 터미널을 2개 열어 **터미널 1(서버용)**과 **터미널 2(러너용)**로 나누어 실행합니다.

---

## 0. 시험 방식 이해

**왜 24시간 대신 30분 집중 시험인가?**
- 사전 점검([`real/check_grasp.py`](../real/check_grasp.py)) 결과, 빈 손 상태에서는 손가락 간 간섭이 없어 부하가 거의 걸리지 않음($0.00 \sim 0.07$ N·m)을 확인했습니다.
- 무부하 상태로 밤새 24시간을 돌리면 모터 온도가 40 °C 부근에서 정체되어 과열 안전장치(65 °C 차단)나 모터 토크 내구성을 유의미하게 검증할 수 없습니다.
- 따라서 **사람이 옆에서 지켜볼 수 있는 30분 동안 집중적으로 가동**하여, 실제 파지 부하 하에서 발열 상승 추이와 제어/통신 연속성을 검증합니다.

**러너가 하는 일** ([`real/endurance.py`](../real/endurance.py))
- 2분(120초)을 한 사이클로 **30초 쥐기 → 90초 펴기**를 반복합니다 (30분 동안 총 15회 파지).
- 5분마다 다음 그립 프리셋(3종: 상자, 물병, 휴지심)으로 순환합니다.
- 실행 명령: `--minutes 30` 옵션 사용.

**자동 안전장치 (실시간 작동)**
- 모터 온도가 **65 °C**를 넘으면 손을 펴고 토크를 끈 뒤 즉시 중단합니다.
- 모터에 하드웨어 오류가 생기면 서버가 그 모터를 **자동 재부팅(Reboot)**해 5초 내 복구합니다.
- 서버와의 통신이 일시 실패하면 경고만 출력하고 재시도하며, **60초 이상 연속 두절 시** 손을 펴고 안전하게 종료합니다.

## 1. 준비 (5분)

### 1-1. 파지 대상물 세팅 (권장)
- 모터에 실질적인 파지 토크 부하가 걸리도록 손 안에 **탄성이 있는 물체(스펀지, 실리콘 볼, 약간 굵은 폼 블록, 빈 물병 등)**를 거치합니다.
- 손이 펴졌을 때 물체가 떨어지지 않도록 가볍게 지지하거나 받침대를 둡니다.
- *(물체가 없더라도 프리셋 3종 자세 전환으로 모터 가동 시험은 가능합니다)*

### 1-2. 하드웨어 점검
- 12 V 전원 어댑터 및 U2D2 케이블 연결 상태 확인
- 모터가 식어 있는 상태에서 시작 (상온 약 25~35 °C)

## 2. 사전 점검: 관절 간섭 및 부하 확인 (기수행 완료)

손가락끼리 부딪히지 않는지 이미 확인을 마쳤습니다.
```bash
python real/check_grasp.py
```
✅ **실측 결과 요약**:
- 모든 그립(상자, 물병, 휴지심, Q_CLOSE 1.0)에서 오차 $\le 0.01$ rad, 무부하 토크 $\le 0.07$ N·m.
- 손가락끼리 부딪히는 간섭(issue #7) 없음 확인 통과.

## 3. 2분 퀵 리허설 (선택, 5분)

30분 본 시험 전 통신 및 1사이클 동작을 점검합니다.

**터미널 1 (서버)**

**터미널 2 (러너 - 1사이클 2분 구동)**

✅ 30초 쥐기 → 90초 펴기 후 요약이 정상 출력되면 통과.

## 4. 본 시험 시작: 30분 집중 구동

> **중요**: 리허설을 마쳤다면 서버 터미널(터미널 1)에서 `Ctrl+C`로 서버를 끈 뒤 다시 실행합니다. (통신 카운터가 0부터 시작해야 30분 통계가 깨끗하게 기록됩니다)

### 4-1. 터미널 1: 서버 실행 (로깅 활성화)
```bash
python real/server.py --log logs
```
- 브라우저에서 `http://127.0.0.1:8000`을 열어 실시간 대시보드를 띄워둡니다.

### 4-2. 터미널 2: 30분 연속 구동 러너 실행
```bash
python real/endurance.py --minutes 30
```
- 그립 3종(상자, 물병, 휴지심)을 5분마다 바꿔가며 30분간 순환합니다.
- 화면에 남은 시간 및 최고 온도가 실시간으로 갱신됩니다.

## 5. 시험 중 모니터링 (수시)

1. **웹 대시보드 (`http://127.0.0.1:8000`)**:
   - 모터별 **온도(Temperature)**와 **부하(Load/Torque)**가 실시간으로 표시됩니다.
   - 특정 모터 온도가 60 °C에 도달하는지 주시합니다 (65 °C 도달 시 러너 자동 차단).
2. **이상 징후 발생 시 비상 정지**:
   - 러너 터미널(터미널 2)에서 `Ctrl + C` $\rightarrow$ 손을 펴고 토크 꺼짐
   - 반응이 없으면 서버 터미널(터미널 1)에서 `Ctrl + C`
   - 물리적 비상 정지: 모터 12 V 전원 플러그 뽑기

## 7. (별도) 시연용 teleop.py 웹캠 점검 — Windows PC

시연은 Windows 컴퓨터에서 하는데, 지금까지는 WSL2 환경에서 [`src/teleop.py`](../src/teleop.py)를 돌리다가 `cap.read()`에서 멈춰 Ctrl+C로 끊어야 했던 적이 있습니다. 원인이 GUI(Qt) 쪽인지 웹캠 프레임 전달 자체가 막히는 것인지 아직 특정 못 했으므로, 실제 시연 PC에서 미리 확인이 필요합니다.

**증상 요약**
- TFLite/MediaPipe 경고(`feedback manager`, `NORM_RECT` 등)와 `QFontDatabase: Cannot find font directory ...cv2/qt/fonts` 경고는 무해한 로그 노이즈 → 무시 가능
- 몇 프레임 처리 후 `cap.read()`가 응답 없이 멈춤 → Ctrl+C로만 종료됨 (WSL2에서 웹캠을 usbipd로 패스스루할 때 자주 생기는 현상)

**확인할 것**
- [ ] 시연 PC(Windows)에서 WSL2 없이 **Windows 네이티브 파이썬**으로 `teleop.py`를 돌릴 수 있는지 먼저 검토 (웹캠 접근이 훨씬 안정적)
  - 이 경우 `--url`을 WSL2 쪽 서버 IP(`http://<WSL2 IP>:8000`)로 지정해야 함
- [ ] 굳이 WSL2에서 돌려야 한다면: `usbipd attach --wsl --busid <번호>`로 웹캠을 붙인 뒤 `/dev/video0` 등이 보이는지 확인
- [ ] `~/mujoco_env/bin/python src/teleop.py --no-preview`로 먼저 돌려서, GUI(`cv2.imshow`) 없이도 똑같이 멈추는지 확인 → 멈추면 웹캠/드라이버 쪽 문제, 안 멈추면 GUI 쪽 문제로 범위를 좁힘
- [ ] 몇 분 이상 끊김 없이 프레임을 받는지 (짧게 돌다 멈추는 패턴이 재현되는지)

**재현되면 그때 고칠 것**
- [ ] `run()`의 while 루프를 `try/finally`로 감싸서 Ctrl+C로 끊겨도 `cap.release()`가 항상 불리게 수정
- [ ] 필요하면 `cap.read()`에 타임아웃/워치독을 둬서 무한 대기 대신 에러 메시지를 내고 종료하게 수정
