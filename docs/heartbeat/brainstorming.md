# Tri-hand 비트 연출 프로젝트: 구현 계획

> 이전 초안의 "평면 → 세움 → 움켜쥠" 서사와 에너지 기반 규칙은 폐기함.
> 영상 자동 포즈 추정, 실시간 오디오 반응, 1:20 이후 구간, 곡 교체 지원은 하지 않음.

---

## 1. 목표와 전제

**목표**: 스크립트를 실행하면 음원이 재생되고, 손이 정해진 모션을 **박자에 맞춰** 수행한다.

**전제**
1. 영상(0:00~1:20)을 보고 **모션 A~E(5개 이하)를 사람이 정의**한다. 코드/관절값까지 완성하지 않아도 되며, 동작 설명 + 박자 길이 + 대략적인 손가락 움직임이면 충분.
2. 정의된 모션을 **등간격 비트 격자 + 규칙 기반 구간 표**로 실행한다. 영상은 실행 시 사용하지 않는다.
3. MuJoCo에서 먼저 검증하고, 같은 모션/시간표를 실물 로봇에 이식한다.
4. 로봇은 소리에 반응하지 않는다. 미리 계산한 비트 격자와 구간 표로 재생한다.

## 2. 확정된 음원 격자 (측정값)

| 항목 | 값 | 비고 |
|---|---|---|
| 템포 | **135.000 BPM** | 비트 시각 192개 최소제곱 맞춤. 136이 아님 |
| 1박 | 444.444 ms | `60 / 135` |
| 1마디 (4박) | 1.77778 s | |
| 첫 다운비트 | **0.422 s** | 클릭 트랙 phase0으로 청취 확인 |
| 재생 구간 | **마디 1~45 = 180박 = 80.000 s** | 0.422 s ~ 80.422 s |
| 마디 `k` 시작 시각 | `0.422 + (k−1) × 1.77778 s` | 누적 오차 없음 |

**왜 135이고 136이 아닌가**: 136으로 가정하면 80초 지점에서 약 601 ms(1.35박) 어긋남. 135는 8.6 ms 오차로 실용상 무시 가능.

**왜 등간격 격자인가**: librosa 검출 비트 시각은 23 ms 프레임에 양자화되어 있어 그대로 쓰면 명령이 들쭉날쭉 나감. 상수 4개(`bpm`, `first_downbeat`, `beats_per_bar`, `bars`)로 격자를 수식으로 계산하는 것이 더 안정적.

## 3. 하드웨어 한계와 동작 설계 제약

| 항목 | 값 | 출처 |
|---|---|---|
| 관절 | A_j0(엄지 요, ±1.0472 rad), A_j1/j2, B_j1/j2, C_j1/j2 (7개) | `src/hand.xml` |
| 오므림 부호 | A: −, B·C: + | `src/run_sim.py CLOSE_SIGN` |
| 안전 가동 범위 | j1: 0~0.3 rad, j2: 0~1.2 rad | `src/run_sim.py Q_CLOSE` |
| 서보 | XL430-W250, 토크 1.4 N·m | `AGENTS.md` |
| 속도 상한 | 3.0 rad/s | `AGENTS.md` |

**박 길이별 가능한 동작**:

| 동작 | 필요 속도 | 가능 여부 |
|---|---|---|
| j2 전체 진폭(1.2 rad) **편도**, 1박(444 ms) | 2.70 rad/s | ○ 여유 10% |
| j2 전체 진폭 **왕복**, 1박 | 5.40 rad/s | **✗ 불가** |
| j2 전체 진폭 왕복, 1마디(1.778 s) | 1.35 rad/s | ○ |
| 8분음표 왕복, 진폭 0.3 rad | 2.70 rad/s | ○ |

- **큰 왕복 동작은 최소 2박** 필요. "꽉 쥐었다 펴기"는 1마디 단위.
- `j1` 범위(0~0.3 rad)가 좁아 눈에 보이는 큰 동작은 **`j2`와 `A_j0`(±1.0472 rad)가 담당**.
- `A_j0`(엄지 요)을 주 동작축으로 쓴다.

## 4. 동작 A~E 정의 (채워야 할 표)

한 동작 = 1마디(4박) 안에 끝나는 패턴. **도착 시점을 박에 정렬**한다(출발이 아닌 도착).

| ID | 이름 | 사용 관절 | 길이(박) | 강도 | 비고 |
|---|---|---|---|---|---|
| A | (미정) | | 4 | | |
| B | (미정) | | 4 | | |
| C | (미정) | | 4 | | |
| D | (미정) | | 4 | | |
| E | 정지 | 모두 0 | 4 | - | 마무리/브레이크 |

추가로 기록하면 규칙 설계에 도움이 되는 것: 각 동작이 **어느 에너지 구간(도입/빌드/절정/마무리)에 어울리는지**, 이전 동작에서 자연스럽게 이어지는지.

---

## 5. 구간 표 초안 (에너지 측정 기반, 수정 가능)

librosa로 측정한 마디별 RMS 에너지를 바탕으로 한 초안. **직접 수정해 사용**.

| 구간 | 마디 | 시각 | 에너지(0~1) | 사용 동작 |
|---|---|---|---|---|
| 도입 | 1~8 | 0.4 ~ 14.6 s | 0.29 → 0.48 | A |
| 빌드 | 9~26 | 14.6 ~ 46.6 s | 0.48 → 0.60 | B (4마디마다 C) |
| 절정 | 27~39 | 46.6 ~ 69.8 s | 0.74 ~ 0.99 | D |
| 마무리 | 40~45 | 69.8 ~ 80.4 s | 0.82 → 1.00 | E |

에너지 급변 지점: 마디 26→27 (+0.32, 가장 큰 상승), 마디 29→30 (-0.21), 마디 39→40 (-0.17).

## 6. 싱크 전략

- **마스터 클럭**: `sounddevice` 콜백이 넘긴 재생 완료 샘플 수 ÷ sr = 음원 시각 `t`. `pygame.mixer + perf_counter()`는 play() 지연을 알 수 없어 쓰지 않음.
  ```
  t = 재생된_샘플수 / sr − stream.latency + AUDIO_OFFSET
  ```
- **도착 정렬**: `choreo(t)` 함수는 박 시각에 목표 자세가 *도달*하도록 키프레임을 계산. 출발이 아닌 도착이 눈에 맞아 보임.
- **지연 보정**: `LEAD` 상수 하나로 명령을 미리 보냄. `choreo(t + LEAD)`. MuJoCo와 실물이 다른 값을 쓸 수 있도록 호출부에 둠.
- **실물**: Dynamixel Time-based Profile + Sync Write. U2D2 레이턴시 타이머 1 ms 설정(윈도우 COM 포트 속성).

## 7. 파일 구성

```
src/heartbeat/
  grid.json        # 비트 격자 상수: bpm, first_downbeat, beats_per_bar, bars
  motions.json     # 동작 A~E 키프레임 (0~1 정규화 오므림량, A_j0만 rad)
  schedule.json    # 구간 표 + 규칙 파라미터
  grid.py          # 마디·박 ↔ 초 변환. 순수 함수, 외부 의존 없음
  choreo.py        # choreo(t) → {관절명: rad}. MuJoCo/실물 공용 순수 함수
  schedule.py      # schedule.json → 마디별 동작 목록
  validate.py      # 안전·속도·정렬 자동 검사
  play.py          # 진입점: 음원 재생 + 시간표 실행 (--headless / --motors)
docs/heartbeat/
  Heartbeat.mp3
  heartbeat.mp4
tests/test_heartbeat.py
```

기존 `src/run_sim.py`의 `CLOSE_SIGN`, `Q_CLOSE`, `apply_ctrl`과 `src/motors.py`의 `HandMotors`를 그대로 재사용. 중복 구현 금지.

### 데이터 형식

**grid.json**
```json
{ "bpm": 135.0, "first_downbeat": 0.422, "beats_per_bar": 4, "bars": 45 }
```

**motions.json** — 0~1 정규화 오므림량. 적지 않은 관절은 이전 자세 유지. A_j0만 rad.
```json
{
  "A": {
    "label": "가벼운 까딱임",
    "beats": 4,
    "keyframes": [
      { "beat": 1, "q": { "B_j2": 0.5, "C_j2": 0.5 }, "ease": "out" },
      { "beat": 3, "q": { "B_j2": 0.0, "C_j2": 0.0 }, "ease": "out" }
    ]
  }
}
```

**schedule.json**
```json
{
  "sections": [
    { "bars": [1,  8],  "motion": "A" },
    { "bars": [9,  26], "motion": "B", "every": { "4": "C" } },
    { "bars": [27, 39], "motion": "D" },
    { "bars": [40, 45], "motion": "E" }
  ],
  "rules": { "accent_first_beat_scale": 1.15 }
}
```

## 8. 검증 규칙 (자동 실행)

실행 전 전체 시간표를 검사. 위반 시 어느 마디·동작인지 출력하고 중단.

| # | 검사 | 기준 |
|---|---|---|
| 1 | 목표 각도 안전 범위 | j1 0~0.3, j2 0~1.2, A_j0 ±1.0472 rad |
| 2 | 키프레임 간 속도 | `\|Δq\| / Δt ≤ 3.0 rad/s` |
| 3 | 도착 시각 격자 정렬 | 박 또는 8분음표 단위 |
| 4 | 시간표 길이 | ≤ 45마디 (80.422 s) |
| 5 | 자가 충돌 없음 | 헤드리스 전구간 실행, 바닥 외 접촉 0 |

## 9. 단계와 완료 기준

Phase별 상세 작업 내용·API·테스트는 **[implementation-plan.md](implementation-plan.md)** 참조.

| 단계 | 내용 | 완료 기준 | 음원·GUI 필요 |
|---|---|---|---|
| 0 | 음원 격자 확정 | `grid.json` 커밋 (BPM 135, 첫 박 0.422 s) | ✅ 완료 |
| 1 | `grid.py` 단위 테스트 | 45마디 시각 수식 검증, pytest 통과 | 불필요 |
| 2 | `motions.json` A~E 초안 + `choreo.py` | `choreo(t)` 7관절 반환, 검증 1~4 통과 | 불필요 |
| 3 | `schedule.py` 구간 표 적용 | 45마디 시간표 생성, 검증 전항 통과 | 불필요 |
| 4 | 헤드리스 전구간 시뮬 | 발산 없음, 자가 충돌 0, 추종 오차 → `LEAD` 확정 | 불필요 |
| 5 | `play.py` 음원 + 뷰어 | 눈·귀로 박자 일치, `AUDIO_OFFSET` 보정 | **필요** |
| 6 | 실물 이식 | 같은 시간표 재생, 지터 측정 | 실물 |

1~4단계는 음원도 GUI도 없이 완료 가능 (AGENTS.md 헤드리스 원칙).

## 10. 환경

- **오디오 재생**: `sounddevice` + `soundfile`. 재생 샘플 수를 마스터 클럭으로 사용. `requirements.txt`에 추가.
- **음원 분석**: `librosa` + `soundfile`. ffmpeg 불필요(soundfile이 mp3 직접 디코딩). `requirements-analysis.txt`에 분리.
- **영상**: 실행에 사용하지 않음. `opencv-python`은 분석 의존성에서 제거.
- **실행 환경**: 윈도우 네이티브 권장 (음원 출력, GUI 뷰어, U2D2 COM 포트).
- **경로**: `pathlib.Path(__file__)` 기준으로 작성해 OS 의존 없앰.
